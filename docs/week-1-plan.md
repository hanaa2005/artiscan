# برنامه هفته اول — ArtiScan

این سند برنامه‌ای است که هفته اول بر اساس آن اجرا شد، به همراه وضعیت نهایی هر مرحله.

## هدف

ساخت هسته فرانت‌اند و سیستم ثبت رویداد: یک نمونه اولیه که بتواند فرایند نقاشی را
به‌صورت داده ساختاریافته ثبت، ذخیره، صادر و بازسازی کند.

**اصل معماری حاکم بر کل پروژه:** Event Log داده اصلی سامانه است. تصویر نهایی، آمار و هر
گزارش آینده از روی همان رویدادها **ساخته** می‌شوند، نه برعکس.

## محدوده

### داخل محدوده هفته اول

بوم رویدادمحور، قلم و پاک‌کن، Undo/Redo/Clear، Action Log، خروجی و ورودی JSON، بازسازی
از JSON، خروجی PNG، پنل اطلاعات، ذخیره خودکار، تست‌های واحد، مستندات.

### خارج از محدوده (آگاهانه)

Backend، FastAPI، دیتابیس سمت سرور، احراز هویت، WebSocket، Redux/Zustand، React Router،
Tailwind، هوش مصنوعی، مدل روان‌شناختی، تحلیل احساسات، API خارجی، Cloud Storage، Docker،
PWA، Microservice، Deployment.

همچنین **بازپخش انیمیشنی و Timeline** به هفته دوم موکول شد.

## تصمیم‌های اتخاذشده در حین اجرا

هر کدام از این‌ها یک انتخاب کوچک بود که برای شفافیت مستند شده است:

| تصمیم | دلیل |
|---|---|
| مسیر پروژه `C:\Users\ASUS\ArtiScan` | Workspace خودِ پوشه Home بود؛ ساختن `node_modules` مستقیماً در آن مناسب نبود. |
| افزودن `hasRealPressure` به `DrawingStroke` | تا در تحلیل‌های بعدی بتوان خطوط قلم واقعی را از موس و لمس جدا کرد. |
| شمارنده `sequence` مشترک بین نقاط و رویدادها | خواندن Log مرتب‌شده بر اساس `sequence` دقیقاً ترتیب واقعی اتفاقات را بازتولید می‌کند. |
| مقداردهی `order` هنگام ساخت خروجی | Undo و Redo ترتیب آرایه را عوض می‌کنند؛ مقدار ثبت‌شده هنگام رسم کهنه می‌شد. |
| Clear غیرقابل بازگشت | مدل داده ساده می‌ماند؛ در عوض یک پیام تایید اضافه شد. |
| بنر بازیابی، جلسه قبلی را حذف نمی‌کند | یک کلیک اشتباه نباید کار قبلی کاربر را نابود کند. |
| `fake-indexeddb` به‌عنوان devDependency | تا لایه IndexedDB واقعاً تست شود، نه فقط مسیر «در دسترس نیست». |
| نصب نشدن `@testing-library/react` | تست رندر بوم در jsdom ارزش افزوده کمی دارد؛ تست‌ها روی منطق خالص متمرکز شدند. |
