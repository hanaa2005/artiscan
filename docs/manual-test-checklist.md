# چک‌لیست تست دستی — ArtiScan هفته اول

تست‌های خودکار (`npm run test`) منطق خالص را پوشش می‌دهند: مختصات، آمار، اعتبارسنجی،
Serialization و لایه IndexedDB. آنچه **فقط با دست** قابل بررسی است — رفتار واقعی ورودی و
رندر بوم — در این چک‌لیست آمده است.

## آماده‌سازی

```bash
npm install
npm run dev
```

سپس آدرس `http://localhost:5173` را باز کنید و **Console مرورگر** را باز نگه دارید
(کلید `F12`). پنل «اطلاعات جلسه» را هم باز بگذارید تا شمارنده‌ها را ببینید.

---

## ۱. رسم با موس

- [ ] با نگه‌داشتن دکمه چپ موس یک خط بکشید. خط باید **بدون تأخیر محسوس** دنبال موس بیاید.
- [ ] «تعداد خطوط» به ۱ و «تعداد کل نقاط» به عددی بزرگ‌تر از ۱ افزایش یابد.
- [ ] «نوع آخرین ورودی» مقدار **موس** را نشان دهد.
- [ ] «مدت جلسه» در حال افزایش باشد.
- [ ] یک کلیک ساده (بدون حرکت) هم یک نقطه ثبت کند.
- [ ] کلیک راست روی بوم **نباید** خط ایجاد کند.

## ۲. Pointer Capture — مهم‌ترین تست ورودی

- [ ] از وسط بوم شروع به کشیدن کنید، **بدون رها کردن دکمه** موس را به بیرون از بوم ببرید،
      کمی حرکت دهید و دوباره به داخل بوم برگردید، سپس رها کنید.
- [ ] خط باید **یک Stroke پیوسته** باشد و در لبه بوم قطع نشده باشد.
- [ ] «تعداد خطوط» فقط ۱ واحد اضافه شده باشد (نه ۲ یا بیشتر).

## ۳. رسم با لمس (اگر دستگاه لمسی دارید)

اگر دستگاه لمسی ندارید، در Chrome با `F12` → آیکون Device Toolbar (`Ctrl+Shift+M`) حالت
لمسی را شبیه‌سازی کنید.

- [ ] با انگشت روی بوم بکشید؛ خط ثبت شود.
- [ ] هنگام کشیدن روی بوم، **صفحه Scroll نشود** (اثر `touch-action: none`).
- [ ] «نوع آخرین ورودی» مقدار **لمس** را نشان دهد.
- [ ] «فشار واقعی قلم» باید **ثبت نشده** بماند (فشار لمس ثابت است و عمداً ذخیره نمی‌شود).

## ۴. رسم با قلم (اگر قلم دیجیتال دارید)

- [ ] با قلم بکشید؛ «نوع آخرین ورودی» مقدار **قلم** را نشان دهد.
- [ ] «فشار واقعی قلم» به **ثبت شده** تغییر کند.
- [ ] در فایل JSON خروجی، مقدار `pressure` برای این خط عددی (نه `null`) باشد.

## ۵. قلم و پاک‌کن

- [ ] چند خط رنگی بکشید.
- [ ] رنگ را عوض کنید و خط جدیدی بکشید؛ رنگ جدید اعمال شود.
- [ ] ضخامت را روی حداکثر ببرید و بکشید؛ خط ضخیم شود.
- [ ] ابزار «پاک‌کن» را انتخاب کنید و روی خطوط بکشید. باید **پاک شوند**، نه اینکه با
      رنگ سفید روی آن‌ها کشیده شود (روی پس‌زمینه غیرسفید هم امتحان کنید اگر ممکن است).
- [ ] در پنل، «خطوط قلم / پاک‌کن» باید هر دو شمارنده را جدا نشان دهد.
- [ ] «تعداد رویدادها» با هر تغییر ابزار/رنگ/ضخامت افزایش یابد.

## ۶. Undo، Redo و Clear

- [ ] سه خط بکشید، سه بار «واگرد» بزنید؛ خطوط یکی‌یکی حذف شوند.
- [ ] وقتی چیزی برای واگرد نمانده، دکمه **غیرفعال** شود.
- [ ] سه بار «ازنو» بزنید؛ خطوط به همان ترتیب برگردند.
- [ ] «تعداد واگرد» و «تعداد ازنو» در پنل درست شمرده شوند.
- [ ] پس از یک واگرد، **یک خط جدید بکشید**؛ دکمه «ازنو» باید غیرفعال شود (تاریخچه ازنو
      باطل می‌شود).
- [ ] «پاک کردن همه» یک پیام تایید فارسی نشان دهد. با «لغو» هیچ اتفاقی نیفتد.
- [ ] با تایید، بوم خالی شود و «خطوط قابل مشاهده» صفر شود، اما «خطوط ثبت‌شده (کل)»
      **تغییر نکند** — این تفاوت عمدی است.

## ۶.۱ Clear نباید داده پژوهشی را نابود کند

این مهم‌ترین تست جدید است.

- [ ] **۴ خط** بکشید. پنل باید «خطوط ثبت‌شده: ۴» و «خطوط قابل مشاهده: ۴» نشان دهد.
- [ ] «پاک کردن همه» را بزنید و تایید کنید. بوم خالی شود.
- [ ] پنل: «خطوط ثبت‌شده (کل)» همچنان **۴** بماند و «خطوط قابل مشاهده» **۰** شود.
- [ ] «خروجی JSON» بگیرید و فایل را باز کنید:
  - [ ] آرایه `strokes` باید هر **۴ خط** را با تمام نقاط، زمان‌بندی و ابزارشان داشته باشد
        (نه `[]`).
  - [ ] در `actions` یک رویداد با `"type": "clear"` باشد که
        `payload.affectedStrokeIds` آن **شناسه همان ۴ خط** را فهرست کرده باشد.
- [ ] حالا **یک خط جدید** بکشید. فقط همان خط جدید روی بوم دیده شود، نه ۴ خط قبلی.
- [ ] پنل: «خطوط ثبت‌شده» ۵ و «خطوط قابل مشاهده» ۱ شود.
- [ ] دوباره «خروجی JSON» بگیرید و فایل را با «ورود JSON» وارد کنید:
  - [ ] بوم باید **فقط خط پنجم** را نشان دهد (بازپخش درست Clear).
  - [ ] «خطوط ثبت‌شده» همچنان ۵ باشد.
- [ ] صفحه را Reload کنید و جلسه را بازیابی کنید؛ همان نتیجه (فقط خط پنجم) دیده شود.

## ۷. تغییر اندازه صفحه (Resize)

- [ ] یک نقاشی با چند خط در نقاط مختلف بوم بکشید.
- [ ] پنجره مرورگر را **باریک و پهن** کنید.
- [ ] نقاشی باید متناسب کوچک و بزرگ شود و **نسبت‌ها به هم نریزد**.
- [ ] «اندازه بوم» در پنل به‌روز شود، اما «تعداد خطوط» و «تعداد کل نقاط» **تغییر نکنند**
      (داده خام نباید تحت تأثیر نمایش قرار بگیرد).
- [ ] پس از Resize، رسم یک خط جدید در محل درست انجام شود.

## ۸. خروجی JSON

- [ ] دکمه «خروجی JSON» را بزنید؛ فایلی دانلود شود.
- [ ] نام فایل شامل **شناسه کوتاه جلسه و تاریخ** باشد، مثل
      `artiscan-session-fcaefe88-2026-08-09.json`.
- [ ] فایل را با یک ویرایشگر متن باز کنید. باید **خوانا و تورفتگی‌دار** باشد.
- [ ] بررسی کنید که این‌ها وجود دارند: `schemaVersion`، `timeMs`، `sequence`،
      `normalizedX`، `normalizedY`، `pointerType`، `order`.
- [ ] برای خطی که با موس کشیده شده، `pressure` باید `null` باشد.
- [ ] بخش `actions` شامل رویدادهای Undo/Redo/تغییر ابزار باشد.

## ۹. ورود JSON و بازسازی

- [ ] «پاک کردن همه» را بزنید تا بوم خالی شود.
- [ ] با «ورود JSON» همان فایل دانلودشده را انتخاب کنید.
- [ ] نقاشی باید **دقیقاً مثل قبل** بازسازی شود.
- [ ] «تعداد خطوط» و «تعداد کل نقاط» با مقادیر قبلی یکسان باشند.
- [ ] «شناسه جلسه» به شناسه فایل واردشده تغییر کند.
- [ ] پیام موفقیت فارسی نمایش داده شود.
- [ ] **همان فایل را دوباره** انتخاب کنید؛ باید دوباره کار کند (نه اینکه بی‌اثر باشد).
- [ ] پس از Import یک خط جدید بکشید؛ باید به نقاشی اضافه شود و `timeMs` آن از آخرین زمان
      فایل واردشده **بزرگ‌تر** باشد.

## ۱۰. فایل نامعتبر — نباید Crash کند

برای هر مورد، یک پیام خطای **فارسی و قابل‌فهم** انتظار می‌رود و برنامه باید سالم بماند:

- [ ] یک فایل متنی خالی بسازید (`empty.json`) و وارد کنید.
- [ ] یک فایل با محتوای خراب مثل `{ this is not json` وارد کنید.
- [ ] یک فایل معتبر را کپی کنید و `"schemaVersion": 1` را به `2` تغییر دهید و وارد کنید.
      → پیام باید بگوید نسخه Schema پشتیبانی نمی‌شود.
- [ ] در یک فایل معتبر `"strokes": [...]` را به `"strokes": "abc"` تغییر دهید.
- [ ] در یک نقطه، `normalizedX` را به `5` تغییر دهید. → پیام درباره بازه ۰ تا ۱.
- [ ] یک فایل JSON کاملاً بی‌ربط (مثلاً `package.json` پروژه) را وارد کنید.
- [ ] پس از هر خطا، نقاشی قبلی باید **دست‌نخورده** باقی مانده باشد.

## ۱۱. خروجی PNG

- [ ] چند خط بکشید و با پاک‌کن بخشی را پاک کنید.
- [ ] «خروجی PNG» را بزنید.
- [ ] فایل را باز کنید: پس‌زمینه باید **سفید توپر** باشد، نه شفاف و نه سیاه.
- [ ] ناحیه پاک‌شده باید **سفید** دیده شود (نه سیاه، نه شطرنجی).
- [ ] رزولوشن تصویر باید حدود **دو برابر** اندازه بوم روی صفحه باشد.

## ۱۲. ذخیره خودکار و بازیابی

- [ ] چند خط بکشید و منتظر بمانید تا «ذخیره خودکار» در پنل مقدار **ذخیره شد** بگیرد.
- [ ] صفحه را **Reload** کنید (`F5`).
- [ ] یک بنر فارسی باید بپرسد آیا می‌خواهید جلسه ذخیره‌شده را بازیابی کنید، به‌همراه
      تعداد خطوط و نقاط.
- [ ] «بازیابی جلسه» را بزنید؛ نقاشی برگردد.
- [ ] دوباره Reload کنید و این بار «شروع جلسه جدید» را بزنید؛ بنر بسته شود و بوم خالی
      بماند.
- [ ] در حالت **Private/Incognito** هم برنامه باید کار کند؛ فقط ممکن است «ذخیره خودکار»
      وضعیت غیرفعال نشان دهد.

## ۱۳. جلسه جدید

- [ ] «جلسه جدید» را بزنید و تایید کنید.
- [ ] «شناسه جلسه» باید یک UUID **جدید** باشد.
- [ ] همه شمارنده‌ها صفر شوند و «مدت جلسه» از `0:00` شروع شود.

## ۱۴. کارایی

- [ ] یک خط **بسیار طولانی و پیچیده** بکشید (چند هزار نقطه، حرکت سریع و مارپیچ).
- [ ] رسم باید روان بماند و کند نشود.
- [ ] در Console هیچ اخطاری درباره performance ظاهر نشود.

## ۱۵. Console مرورگر

- [ ] در پایان همه تست‌ها، Console را بررسی کنید.
- [ ] **هیچ خطای قرمزی** نباید وجود داشته باشد.
- [ ] اخطارهای مربوط به React DevTools یا Vite طبیعی هستند و مشکلی ندارند.
